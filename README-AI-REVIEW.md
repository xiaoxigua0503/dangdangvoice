# 商品综合解读 v2 · Node / PostgreSQL / VM

本次不部署。保留现有模型与 endpoint，不合并 QW Pages。HTTP 仅管理 durable jobs；独立常驻 worker 执行推理，继续使用 owner/Pro 检查、租约、心跳、取消、有界重试、私有缓存和中断续跑。

## 内容与数据

主视图是一篇简体中文综合解读：一句购买判断、若干连贯自然段、必要的图文对照和购买前确认事项。无证据就不生成对应部分。轻量“评/图”引用打开本任务保存的原文/原图，也可跳转当当原始地址。没有流式草稿，只有通过验证的综合结果可作为完成报告展示。

代码统计当前快照评论数、非默认且至少十二字的条目、默认评价数、图片地址数、成功下载的哈希去重图片数、未读图片条目。站点宣称评价量单列，不能冒充本次已读范围。模型通过 `statistics` 引用代码统计键；界面渲染实际数字及分母，禁止模型在正文自行生成频率/比例/汇总统计。源中已有型号、价格、日期可保留。

传入实际已采集的商品名、描述、价格、规格/版本等白名单字段，统一标为商家声明；评论保留列表与全文、原始评分、日期、版本、默认标记、来源和图文关联。评分可能沿用站点原始量表，未悄悄转为五星制。新采集的商品页 description / 规格通过客户端、浏览器档案、JSON 导入导出、云快照进入 AI；旧快照没有的字段不会补造，也不自动重新抓取。云记录保留扩展字段，AI 使用白名单，不发送账户名、等级、邮箱或会话。原始自由文本/照片不保证完全没有个人信息。

“查看评论与图片质量”默认收起：程序核对相同原文、SHA-256 相同图片字节，另列默认标记、短文本规则与近似评论规则。近似评论只在相同前缀、最近十二个候选中计算双字 Jaccard ≥ 0.85，披露方法和比较对数，不声称穷举。AI 模板相似、评分与文字差异、可能近似图片单独标识为推断。点击类别筛选关联原件，不删除原始数据，不输出可信度分数，不把负面体验自动归为异常，不作欺诈定性。

## 请求预算与处理流程

已于 2026-11-20 核对[官方模型表](https://help.aliyun.com/zh/model-studio/text-generation-model)和[视觉限制及 token 计算](https://help.aliyun.com/zh/model-studio/vision)：

- `qwen3.7-flash`：1M context、64k 最大输出；实现使用更保守的 1,000,000 context，单次输出仍受配置的 4096（上限8192）约束。
- Base64 最多250张；Data URI 最大20MB；整体请求64MB；旧 DashScope 域名整体16MiB。应用保留更小的单图/总下载/像素限制及 SSRF 防护。
- 每图按官方最高16384视觉 token 加2预留，文本用 UTF-8 字节数作保守 token 上界，并预留8192用于消息封装。**这不是精确分词计数**；实际 token 来自 API usage。Base64 payload 依实际下载字节计算，发送前再次核算。
- 目前只核实了默认 `qwen3.7-flash` 与阿里云官方 endpoint 的 v2 限额。其他配置保持原值，但新任务预检阻止启动，直到补充该模型/端点的已核实预算；不自动切换模型。v1 历史任务继续使用其保存配置。

`prepare` 在 worker 内最多同时下载两张，URL 规范化去重；首次成功字节持久缓存，以 SHA-256 合并 byte-identical 图片的推理输入，保留所有地址及全部评论关联。不给相同图片重复的独立证据权重。不自动缩图或裁图。

能容纳则一个多模态 `review` 请求通读全部评论片段和可读去重图片。超限时按实际预算分成多个图文阅读步骤，关联图片携带完整对应评论上下文；最后一个 durable `synthesis` 请求依据全部已校验阶段结果及原文引用写唯一文章，不冒称再次阅读原图。所有步骤继续有 lease/retry/cache/ownership。未读取的图片和失败阅读步骤明确披露；成功下载不等于成功分析。

未静默抽样、截断或丢弃输入。若连一个完整证据片段或最终全部阶段摘要也超出预算，步骤明确失败、不给拼接结果冒充完成综合报告；已有结果保持可续跑。此版本不实现无限层递归摘要。任务容量还受原有 comments/images/units 与总字节上限约束。

schema / prompt / cache 已版本化。新 Zod schema 验证引用类型、当前步骤证据范围、原文逐字引文、图片文字与评论引文分离、图文关联、近似图片至少两个来源；最终综合只能引用通过校验阶段的证据。限制无依据统计、来源外编号、绝对真伪与群体推广。机械校验不能证明每个语义判断都正确，仍需人工核对。004 迁移仅扩展 unit kind 和增加唯一综合步骤索引；v1 JSON 报告、原输入、缓存不删除，旧报告使用兼容界面读取且隐藏空章节。

## 更新 VM

先备份 PostgreSQL，并记录当前发布版本。停止 worker 领取新工作，等待正在执行的任务结束；已有任务及缓存留在原数据库。使用本分支提交构建 Node 22 发布目录，保留服务器私有环境文件，切勿上传 `.env`。

```bash
npm ci
npm run typecheck
npm run build
node --env-file-if-exists=.env server/migrate.mjs
```

确认迁移已应用至 `006_ai_engine_fingerprint.sql`，再重启现有 VM web 服务与 worker 服务（使用当前运维的 systemd/进程管理器和环境配置，无需新建实例）。web 运行 `npm start`，worker 运行 `npm run ai:worker`，保持同一 PostgreSQL，worker 使用支持会话 advisory lock 的直连地址。继续使用当前 `AI_MODEL`、`AI_BASE_URL`、`AI_API_KEY`，不要复制本地凭据。worker 启动会检查006迁移。

先以 `AI_WORKER_ENABLED=false` 检查 web 登录、历史与报告读取，再按原部署环境开启 worker。单任务验证可额外配置 `AI_WORKER_JOB_ID=<owned-job-uuid>` 限定领取范围；验证后移除该临时限制。未验证 SMTP 投递，不声称邮件可用。

回滚应用前保留004迁移与新报告数据；旧 worker 不理解新 kinds，应先停掉 v2 工作，避免用旧 worker 领取 v2 任务。不要下迁移删除数据。

## 后续修复与真实 UI 验收（接续 8821700，2026-11-20）

本节取代上一节“真实成文尚未验收”的状态：原 local task `5f0e6ad9-7841-404d-b80c-de84ad625c6a` 已形成非 mock 的真实综合报告，逐段复核来源，并在实际登录应用 UI 验收通过。仍未部署 VM/Vercel，未调用 production 应用 API，未执行测试套件。原始快照、评论、图片与其它历史报告保留。

### 根因与修复

- 原输出把商家宣传扩成学术/收藏价值，将图文关联当作真实性证明，并出现跨评论借用事实、正文技术 ID 与错误图片抄字。原检查维持，新增对应的来源/程度/因果和质量标签检查；不以普通负面体验充当异常评价依据。validation 现在返回全部错误位置，失败输出留在私有 `ai_attempts.validation`，不作为完成正文。
- 将失败整篇草稿重新送入模型会造成措辞锚定。retry 改为错误清单与对应原始来源；需要修复时优先只改失败的 scalar 字段，其它模型段落及引用保持原样。每个字段仅收到自己所引评论/既有图片观察，不能借其它字段的事实。所有合并结果再次经过完整 schema、引文、引用类型、来源与语义限制校验。
- 官方[结构化输出说明](https://help.aliyun.com/zh/model-studio/qwen-structured-output)明确：多模态 `json_schema` 自动降为 `json_object`。图文读取继续以应用验证为准；已有视觉观察后的 text-only 局部修订使用真正的 `json_schema` strict 解码，短字符串、固定字段与正文 ID 限制。text-only 不创造新图像细节或新的图文一致/冲突结论。复杂修复 schema 曾导致 output 截断，现优先使用少量 scalar 字段，保留4096输出上限，无模型/endpoint切换。
- 统计口径集中在文章页脚并可展开，段落用轻量“范围”按钮关联，不再重复铺开所有统计数字。报告页脚明确显示经过局部修订及没有重新读图。

### Worker 版本协议与005/006迁移

应用 `005_ai_worker_protocol.sql` 和 `006_ai_engine_fingerprint.sql`，不删除或重建旧数据。worker 在领取事务中声明代码内固定的 pipeline/schema/kind 能力；SQL 查询只选支持的组合。PostgreSQL claim trigger 另行阻止未声明 v2 能力的旧进程领取 v2/future 任务，错误为 `worker_pipeline_incompatible`，发生在插入 attempt/调用 provider 之前。能力声明仅在当前事务有效，防止连接复用留下能力声明。v1 text/image 任务保留兼容通道。

本地检查了仍在运行的旧 worker，已停止该旧进程。以回滚 transaction 验证：无声明的旧 worker 更新 v2 lease 被拒绝，新能力声明被接受；新 worker 对未知 pipeline/schema 不选取。兼容 worker 以 disabled 且指定 task 的方式检查启动，不领取 backlog。生产尚未应用这些迁移。新任务还记录启动时捕获的 engine 源码 fingerprint；即使 pipeline/schema 没变，旧进程也不能领取新代码创建的任务。fingerprint 由固定源码清单生成，不读取密钥；web 和 worker 应使用同一发布物，修改文件后必须重启两者。旧任务没有 fingerprint 时走明确的兼容路径，并记录实际执行版本。

VM 更新仍须先停止旧 worker，备份并应用全部迁移至006，再重启新 web/worker。不要只更新 web 并让旧进程继续存活；DB trigger 是保护，不是代替正常滚动升级。历史任务配置保留创建时的 prompt 版本，新的尝试另记实际 `usage.execution` 及 `usage.repair`，缓存包含实际 prompt 和修复来源 hash。
